# Runtime contract

These skills are instructions plus local scripts, not a hosted application or a provider API. An assistant must be able to read files and run the selected tools. Model access must come from the user's available authenticated tools or UI. Never request or embed passwords in prompts.

Use Python 3 for CLI scripts; Blender with Python for guide rendering; FFmpeg and FFprobe for encoding/probing. Only the camera workflow bundles blender_guide.py. Commands using pipeline.py are supported by workflows that bundle that script. No pip packages are required for pipeline.py. Blender supplies bpy and mathutils.

A route JSON has coordinates="blender-z-up-metres", fps, duration, horizontal_fov, and frames. Each frame has frame (contiguous from 1), position [x,y,z] and target [x,y,z]. Include the endpoint: sample count = duration * fps + 1. Render FPS must sample integer route frames; clip starts/durations must align with the rendered frame grid. Validation checks these constraints before Blender runs. Positions encode eye height and floor changes. GLB import converts glTF coordinates itself; do not double-convert geometry. Supply a .blend already in the documented coordinate system or a conforming GLB.

A project manifest contains project, revision, scene, route, render {fps,width,height,samples}, clips [{start,duration}], invariants and sources. Paths resolve relative to the manifest. Clips must be contiguous and cover the route. Example values are not evidence. Populate source records with file/URL, provenance, depicted areas and scale basis. Keep actual plan interpretation and source-specific scene generation in the project.

For script usage run python3 scripts/pipeline.py --help. Prompt operation takes a template, a JSON values file and a new output file. Missing, blank, null, REPLACE or unresolved-template values fail before writing; use an explicit None or Not applicable string for an intentionally absent optional reference. Encode takes a project manifest, a numbered PNG folder and a new media directory. Assemble takes a config and new output video. Snapshot takes an existing, nonempty protected directory without symbolic links and a new hash record OUTSIDE that directory; verify-assets compares against it. Probe validates metadata and decodes video. All mutating operations use new output paths. Keep source files immutable.

Guide rendering validates the sampled camera against the supplied route; it does not establish spatial clearance, scale, measured accuracy or faithful plan reconstruction. Separate scene-specific continuous clearance tests are required. Media assembly uses hard cuts, no audio and letterboxing; provide other treatments explicitly. Generic tracked repair is not implemented. Do not label an untested provider integration as working.
